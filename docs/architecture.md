# CyberPrior System Architecture

## Current implementation

CyberPrior is an academic vulnerability risk prioritization prototype. It combines public vulnerability intelligence with simulated asset context, calculates project-defined risk labels, compares machine-learning classifiers against those labels, and presents the completed outputs in a local Flask application.

```text
Synthetic asset-vulnerability records
                ↓
NVD + EPSS + CISA KEV enrichment (cached, refreshable)
                ↓
Rule-based inherent and residual risk assessment
                ↓
Model comparison and CVE-grouped evaluation
                ↓
Priority score, remediation category, and SLA
                ↓
Local Flask dashboard and detail views
```

### Processing components

1. **Input data** – `data/raw/CyberPrior_Input_Dataset_v2_1160.csv` contains 1,160 asset-vulnerability records and 58 distinct CVE IDs. Asset properties are simulated project scenarios; CVE identifiers refer to public vulnerabilities.
2. **Enrichment** – `src/objective1_enrichment.py` joins NVD technical details, FIRST EPSS scores, and CISA KEV status by CVE ID. Responses are cached in `data/raw/api_cache/`. Pass `--refresh-intelligence` to retrieve current source records instead of using the cache.
3. **Risk assessment** – `src/risk_engine.py` calculates threat, impact, inherent risk, residual risk, risk class, factor explanations, and recommendations.
4. **Model evaluation** – `src/train_models.py` compares Logistic Regression, Decision Tree, and Random Forest on a stratified record split and a holdout where CVEs do not overlap. The target classes are generated by the CyberPrior risk rules, so this measures reproduction of project labels rather than real incident prediction.
5. **Prioritization** – `src/prioritization_engine.py` scores and ranks records, assigns remediation SLAs, and selects a project-specific action category.
6. **Web demonstration** – `app.py` reads finalized processed CSVs, the evaluation report, and saved model artifacts at startup. It does not fetch intelligence or retrain models when a page loads. The app is bound to localhost for the demo.

## Scope and limitations

The repository contains a local demonstration of Objectives 1 and 2: enrichment, risk assessment, model comparison, prioritization, explanations, and dashboard views. Continuous history and alerting (Objective 3) and budget-constrained investment optimization (Objective 4) are paused future work. The application is not a production security platform. Asset context and action matching are synthetic and project-specific.
