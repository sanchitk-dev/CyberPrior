# CyberPrior Dataset

## Current input

The primary input is `data/raw/CyberPrior_Input_Dataset_v2_1160.csv`.

- 1,160 asset-vulnerability rows
- 58 distinct CVE identifiers
- 20 simulated assets
- Context fields: asset ID/name, criticality, exposure, data sensitivity, and control effectiveness

A row represents one vulnerability associated with one simulated asset. The same CVE may therefore appear in many rows. CVE IDs are public identifiers for disclosed vulnerabilities; the asset names and organizational context values are synthetic scenarios created for this academic project.

## External vulnerability intelligence

The enrichment pipeline joins data by CVE ID from:

- **NVD**: CVSS score/severity, description, CWE, affected products, and publication/update dates.
- **FIRST EPSS**: estimated exploitation probability and percentile. EPSS is time-sensitive and the pipeline stores its score date.
- **CISA KEV**: whether the CVE is listed as known exploited, with catalog metadata when available.

API responses are cached in `data/raw/api_cache/` for reproducibility. Run `python src/objective1_enrichment.py --refresh-intelligence` to bypass the cache and retrieve the latest available source records before regenerating downstream outputs. A normal run uses the cache.

## Generated datasets

The processing pipeline produces these CSV files under `data/processed/` (and Excel exports for manual review):

1. `CyberPrior_Enriched_Dataset_v1.csv` – original asset rows plus NVD, EPSS, and KEV fields.
2. `CyberPrior_Risk_Assessed_Dataset_v1.csv` – threat and impact factors, inherent/residual scores and classes, recommendations, and fallback flags.
3. `CyberPrior_Prioritized_Dataset_v1.csv` – priority score/rank, remediation category, and SLA.

Risk labels are generated by the project's documented rules. The machine-learning target is derived from those same factors; it is not a label from real organizational incidents. Missing CVSS and EPSS values use explicit project fallbacks (5.0 and 0.0) and are flagged in the assessed output.

## Freshness

NVD, EPSS, and KEV may change after a local cache is created. The generated output should be described as current only as of its stored source dates or the most recent refresh run. Refresh intelligence and regenerate dependent outputs before a presentation when current values are required.
