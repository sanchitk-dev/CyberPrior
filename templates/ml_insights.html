Why evaluate unseen vulnerabilities?

CVE (Common Vulnerabilities and Exposures) is the public ID system for disclosed cybersecurity vulnerabilities; for example, CVE-2024-3400. A vulnerability may appear on multiple asset records. We keep all records with the same CVE ID together, so the evaluation measures whether the models can classify project risk labels for vulnerabilities absent from training. This is one evaluation split from {{ cve_count }} CVEs, so the results have a limited sample size.

What do these scores mean?

All scores are percentages: higher is better. Correct overall is how many test records got the right risk category. Precision asks: when a model assigns a category, how often is it right? Recall asks: how many records in that category did it find? Average F1 balances precision and recall while treating all risk categories equally. Weighted F1 also balances them, but gives more weight to categories with more records.

Average F1 is also called “macro F1” in technical reports. These results measure how closely models reproduce project-generated labels, not real-world incident prediction.
